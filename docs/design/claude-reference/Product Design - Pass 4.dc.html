Roast intensity — the tradeoff, if proposed
For one level

The mode switch stays a single, memorable, binary gesture. Every roast line can be hand-tuned once instead of three times. No user has to guess what "medium" feels like before trying it.

For multiple levels

Some users want gentler teasing without losing the voice entirely; others want it sharper for sharing. Fragmenting copy 2-3x is real production cost for a benefit we haven't validated.

Recommendation: ship one Roast voice now; revisit intensity only if retention/sharing data on Roast users specifically asks for it.

11

Final coherence review

Navigation · accessibility · light/dark · Android

Navigation — recommendation: keep five tabs

Today / Circle / Sky / Chart / Ask still cover the product's real destinations. Calendar nests inside Sky (it's the same "what's happening astronomically" question at a different zoom level); Profile hangs off a header avatar rather than taking a tab, since it's visited far less often than any of the five. Ask keeps its tab — it's a distinct input mode, not a feature of another tab.

Alternative considered — 6th tab for Calendar

Tradeoff: a dedicated Calendar tab makes it more discoverable and gives it equal footing with Sky, but iOS tab bars degrade past five items and Calendar's content already overlaps heavily with Sky's transit/lunation material — splitting them risks two half-features instead of one strong one. Not recommended unless usage data shows Calendar needs standalone weight Sky can't carry.

Accessibility audit
Dynamic Type
All sizes are relative; card/table layouts reflow to single-column past accessibility text sizes.
VoiceOver
Every SVG (chart wheels, coordinate rails, nakshatra bands, element bars) carries a full-sentence aria-label — shown throughout Pass 3 §01–04 and here in §01, §06.
Reduce Motion
All entrance/keyframe animation compresses to 0.12s under the media query set in Pass 3's helmet.
Differentiate w/o Color
Calendar tiers use shape (filled/ring/tick), not color, as primary signal (§01). Notification categories use icon + label, never a color key alone.
Touch targets
All tappable rows and chips meet 44pt minimum height even where visual padding reads tighter.
Share-card readability
Cards use the same 3:1-minimum ink/paper contrast as in-app text, never a decorative low-contrast overlay.

Android deltas
Back behavior

System back gesture/button closes sheets and pops detail screens — no in-app back chevron needed on Android where iOS shows one.

Date/time pickers

Birth date/time entry (§02, §05) uses Material's native picker dialogs rather than iOS's inline wheel.

Notification settings

Category toggles (§03) hand off to Android's system notification-channel settings for OS-level control, alongside our in-app preferences.

Subscription management

"Manage subscription" (§07) deep-links to Play Store subscription center instead of the iOS App Store sheet.

Widgets

Android widget picker and resize handles replace iOS's long-press/edit flow; same four widgets, same content rules (§09).

Share sheet

Share cards (§08) hand off to Android's native share sheet in place of iOS's; card design itself is unchanged.

No second visual identity — every delta above is a platform-convention handoff, not a redesign.
