Which artifact governs, by topic — for engineering handoff. Older artifacts are not rewritten; this map only states precedence.

Product Strategy.dc.html remains authoritative for the core product concept. Later passes execute against it visually and structurally; none supersede its strategic intent.

02  Information Architecture

03  Core Product Screens

Visual reference for each major area is whichever pass last touched it — earlier passes on the same area are historical only:

  • Pass 2 / Pass 3 — early screen exploration; superseded wherever Pass 4 covers the same area.
  • Pass 4 — current reference for core screens (Today / Circle / Sky / Chart / Ask) except monetization surfaces.
  • Pass 4.1 — governs monetization-touching screens (see §4), overriding Pass 4 there only.

04  Monetization

Pass 4.1 is authoritative for the tier model: Free → Rewarded Access → Premium.

Rewarded entitlement rules:

  • One ad unlocks one identified content item — not a session or category.
  • Unlocked content stays unlocked; it survives app restart.
  • The same item never asks again.
  • Different content may require another rewarded unlock.
  • Rewarded access is not temporary Premium — it never grants Premium features.
  • Premium access follows the active subscription entitlement only.

05  Brand

Pass 5 is historical exploration only.

Pass 5.1 (Humay Brand Lock) is authoritative for: Humay, the HUMAY wordmark, the occultation mark, app icon, palette, typography, brand voice, the Roast expression, "Humay Premium" naming, launch/store/press lines, motion, and brand misuse rules.

Where Pass 5 and Pass 5.1 disagree, Pass 5.1 wins — no exceptions.

07  Astrology Data Authority

  • All exact chart values, placements, aspects, timing, dashas, pillars, and interpretations shown in design artifacts are prototype content unless independently validated.
  • They must not become engineering fixtures.
  • Deterministic calculation engines are the authoritative source of truth during implementation.
  • Interpretation consumes structured, calculated facts — it does not produce them.
  • The interpretation/LLM layer must never invent positions, degrees, houses, dashas, pillars, or timing.
