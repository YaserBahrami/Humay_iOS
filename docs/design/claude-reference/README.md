# Astara iOS — Design Reference

## Purpose

These files are the approved product and UI/UX reference for Astara iOS. They are reference artifacts, not production application code.

## Current approved direction

- Eclipse visual direction
- Editorial/Classical-derived typography and hierarchy
- Today / Circle / Sky / Chart / Ask primary IA
- Normal and Roast modes
- Western / Vedic / Chinese as native astrology-system experiences
- Compare Systems
- Compatibility / Today Together
- Chart and Sky
- Calendar nested under Sky
- Ask the Stars
- Profile/Settings, notifications, privacy/data controls, sharing, widgets and complete product states
- Free → optional Rewarded Access → Premium monetization hierarchy
- Rewarded ads only; no banner, native-feed, interstitial or launch ads in the approved product direction

## Artifact roles

**Product Strategy** → product principles, IA and design-system reasoning

**Onboarding** → onboarding and initial chart-reveal reference

**Pass 2** → Today, Circle and compatibility foundation

**Pass 3** → Chart, Sky, native astrology systems, Compare Systems and Ask the Stars

**Pass 4** → Calendar, Profile/Settings, notifications, privacy/data controls, saved-people management, relationship-system depth, Premium, sharing, widgets, application states and coherence review

**Pass 4.1 — Rewarded Access** → optional rewarded-ad access model, Premium coexistence, entitlement states, ad failure/confirmation states, advertising privacy entry and Free/Rewarded/Premium access matrix. Pass 4 remains unchanged; 4.1 is an additive monetization reference.

## Source-of-truth rule

Astrological facts such as planetary positions, Ascendant, houses, aspects, sidereal placements, nakshatras, dashas, BaZi pillars, and transit timing must ultimately come from deterministic calculation engines. Interpretation/design copy must never become the source of truth for astronomical calculations.

## Monetization rule

The approved hierarchy is **Free → optional Rewarded Access → Premium**. Free must remain useful. Rewarded ads are voluntary and unlock bounded pieces of depth; they must never autoplay or interrupt normal reading flows. Premium provides persistent, uninterrupted access without rewarded-unlock prompts. Exact limits, ad provider, consent implementation and entitlement backend remain implementation decisions unless explicitly frozen later.

## Naming

"Ortus" appears in some historical screens as a temporary working/design placeholder name — it is not a decided product name. **Astara** is the repository/project name currently in use and is not yet treated as the final consumer brand unless approved in the branding phase.

## Known unresolved methodology / product decisions

- BaZi Da Yun / Luck Pillar methodology and any required sex-at-birth input remain unresolved.
- Western composite-chart technique choice remains open.
- Exact non-romantic Vedic relationship dimension set remains open.
- Supported advanced house systems, ayanamsas and Chinese calendar conventions beyond defaults remain open.
- Cross-system mapping of a single Western lunation to native Vedic/Chinese timing concepts requires event-specific methodology.
- Final rewarded-ad frequency/limit values and ad provider/privacy implementation remain to be frozen during engineering/product implementation.
