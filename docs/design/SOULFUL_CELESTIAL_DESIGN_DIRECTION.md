# Soulful Celestial Design Direction

**Status:** Legacy post-onboarding reference; retained D1 onboarding authority
**Approved visual source:** D0 Light/Dark references selected on 2026-08-12  
**Scope:** Humay iPhone + iPad UI, Light + Dark appearance, illustration language, components, motion and hierarchy

> As of 2026-08-19, [`PREMIUM_CELESTIAL_REDESIGN.md`](PREMIUM_CELESTIAL_REDESIGN.md) supersedes this document for post-onboarding visual treatment and information architecture. Keep this document for implemented onboarding authority and historical behavior/state context only.

## 1. Product feeling

Humay should feel **warm, alive, friendly, colorful and premium** without becoming childish or visually busy.

The direction is **cosmic editorial with selective cute illustration**:

- serious enough to trust;
- playful enough to have personality;
- colorful in controlled places;
- clean enough for long-form astrology content;
- cute in illustration, not cartoon-heavy in layout;
- modern Apple-platform UI first, astrology styling second.

The D0 Today, Daily Horoscope and Compatibility Light/Dark references under `soulful-reference/anchors/` are the visual source of truth.

## 2. Device composition — iPhone + iPad

Humay is designed for both platforms from the same design system, but not from one stretched layout.

### iPhone

- portrait-first composition;
- compact single-column reading flow;
- feature art stays subordinate to usable vertical space;
- bottom/tab navigation follows the approved product IA.

### iPad

- portrait and landscape are both supported;
- constrain long-form reading text to a comfortable measure instead of spanning the full display;
- use two-column or master/detail composition only when it improves comprehension;
- allow hero art and compatibility/profile regions to sit beside content where appropriate;
- preserve generous margins without turning the layout into empty space;
- support narrower multitasking/split-view widths by collapsing back toward the compact composition;
- do not scale every radius, icon and type size proportionally just because the canvas is larger.

For each screen, the reference package must state whether iPad uses the same hierarchy with a bounded column or a materially different composition.

## 3. Visual intensity

### Level A — Hero
Use once on an emotional screen: Today cosmic weather, Compatibility hero, onboarding welcome/reveal, selected premium moments.

### Level B — Illustrated feature
Use for Love, Career, Money/Finance, Health, Roast, system selection, important Sky events and similar feature cards.

### Level C — Utility
Forms, settings, lists, technical chart rows, calendars and dense information stay quiet and mostly native.

## 4. Illustration language

### Approved

- simple flat/vector or thin-line celestial illustration;
- hand-drawn feeling without looking rough;
- friendly sun, moon, planets, coffee cup, crystal ball, lion and similar objects used selectively;
- very limited facial expressions on selected illustrations;
- small stars, sparkles, orbit lines and dotted connectors;
- soft geometric tint circles behind category icons;
- portrait circles for people/compatibility;
- minimal shading and simple color blocking.

### Do not use

- watercolor/gouache landscapes;
- painterly storybook scenes;
- complex botanical illustration;
- 3D emoji or glossy mascot rendering;
- chibi proportions;
- thick cartoon outlines;
- sticker-sheet density;
- generic purple-neon galaxy backgrounds;
- glassmorphism as the default surface treatment;
- decorative stars on every card.

The app should feel illustrated, not illustrated everywhere.

## 6. Typography

- **Cormorant Garamond** — Humay wordmark only.
- **Newsreader** — editorial/display roles, including large headings and reading headlines.
- **SF Pro / system** — body, navigation, forms, buttons, settings, card labels and most UI.
- **SF Mono / system** — degrees, coordinates and technical date/time values only where scanning benefits.

Large serif typography provides soul; system typography keeps the product modern and readable. iPad may use slightly larger editorial display sizes where the composition supports them, but body sizes remain Dynamic-Type driven rather than device-scaled.

## 7. Surfaces and geometry

- Feature cards: typically 18–24 pt radius.
- Compact rows/cards: typically 14–18 pt radius.
- Primary buttons: pill or high-radius control, visually simple.
- Light mode: subtle borders and very soft elevation only when needed.
- Dark mode: tonal card separation before shadows.
- Controls and forms remain crisp; decorative texture is not part of the direction.
- iPad layouts use max-width/content-column rules instead of globally enlarging cards.

## 8. Core recurring UI language

- warm editorial greeting/headline;
- small playful object illustration beside rather than behind text;
- dark cosmic-weather/daily-tip card used as a strong contrast surface;
- soft category circles for Love/Career/Money/Health;
- Roast card with one playful character/object;
- segmented day selector;
- portrait medallions + dotted connection line in Compatibility;
- large serif compatibility score plus simple metric bars;
- clean product navigation with line icons;
- sparse star/sparkle decoration.

## 9. Canonical information architecture

The historical IA was **Today / Circle / Sky / Chart / Ask**. Current post-onboarding IA is defined only by [`PREMIUM_CELESTIAL_REDESIGN.md`](PREMIUM_CELESTIAL_REDESIGN.md).

On iPad, navigation may present differently when appropriate to the platform, but route hierarchy and feature ownership do not change.

## 10. Onboarding direction

Canonical onboarding is four beats:

1. **Welcome** — strongest personality moment.
2. **Birth Date** — utility-first date input.
3. **Tradition** — Western / Vedic / Chinese choice.
4. **Profile Reveal** — second strongest emotional moment.

Birth time and birth location are not onboarding steps. They may be added later for precise chart features.

From Step 03 onward, every design pass is produced as iPhone + iPad, Light + Dark. Welcome and Birth Date require iPad companion references before cross-device implementation is considered complete.

## 11. Motion

- tiny sparkle appearance;
- slow orbit on selected hero graphics;
- soft card/row entrance;
- matched-geometry transitions where useful;
- gentle haptics for confirmation.

No looping mascot motion or busy particle backgrounds. Respect Reduce Motion.

## 12. Accessibility

- Dynamic Type hierarchy survives accessibility sizes;
- forms and rows reflow instead of shrinking important text;
- minimum touch targets remain 44 pt;
- Light and Dark contrast are tested independently;
- color is never the only carrier of meaning;
- decorative illustration never substitutes for factual labels;
- iPad keyboard/pointer navigation must not be broken by custom controls;
- unknown/unavailable astrology facts remain explicit.

## 13. Asset strategy

Design references live under `docs/design/soulful-reference/`. Reference mockups are not automatically production assets. Approved shipping art is exported/optimized separately into `Humay/Resources/Assets.xcassets/`.

## 14. Visual completion rule

A shipping screen is visually complete only when:

1. iPhone Light is approved;
2. iPhone Dark is approved;
3. iPad Light is approved;
4. iPad Dark is approved;
5. landscape/adaptive iPad behavior is documented when needed;
6. hierarchy matches D0;
7. product/access semantics are current;
8. accessibility risks are recorded;
9. reusable components/assets are identified separately.
